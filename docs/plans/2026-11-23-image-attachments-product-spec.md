# 图片附件产品需求

状态为待评审。本文定义 Westie 会话输入框的图片输入体验和验收标准。

## 当前实现

Web 和 macOS 桌面版共用会话输入框。用户打开会话后输入文字，点击「发送」发起一轮运行（Run）。运行中可以点击「插话」追加文字，两种操作使用各自的请求入口。新一轮运行要求非空文本，用户消息在会话历史中以纯文本展示。当前从输入框到模型的用户消息链路只承载文本。 [输入框](../../web/src/components/ConversationComposer.tsx) · [运行入口](../../src/http/conversation-run-sse-route.ts) · [用户消息展示](../../web/src/components/ConversationTurn.tsx) · [模型输入消息](../../src/transcript.ts)

## 存在的问题

用户想让 Agent 分析界面截图、报错截图或设计参考时，只能在输入框里用文字转述，容易漏掉图片中的布局、文字和其他细节。后续回看会话时，也无法在问题旁看到用户当时提供的原图。

## 目标实现

例如，用户选择 `checkout.png`，在缩略图旁输入「截图中的支付失败提示出现在哪个位置？」，然后点击「发送」。会话历史在同一条用户消息里显示问题和图片。模型收到文字和图片，基于截图回答。用户刷新会话后仍能打开该图片。

首版适用于 Web 和 macOS 桌面端可发送消息的会话，覆盖首条消息和后续轮次。用户通过文件选择器添加本地图片，可发送纯文字、纯图片或图文消息。运行中插话、剪贴板粘贴、拖放、图片编辑、其他文件类型和模型生成图片留待后续评估。

## 具体改动

### 添加和发送

| 场景 | 用户体验 |
| --- | --- |
| 选择图片 | 输入框提供「添加图片」按钮，打开系统文件选择器并支持多选。关闭选择器时保留当前草稿。 |
| 编辑草稿 | 已添加图片按选择顺序显示缩略图和文件名。点击缩略图可查看大图，每张图片可单独移除。切换会话时，未发送的图片随文字草稿一起清空。选择时仅在本机预览，点击「发送」后才提交图片。 |
| 发送 | 非空文本和有效图片满足任一项即可发送。文字和图片作为同一条用户消息提交，保留图片顺序。校验或提交期间禁止重复发送。 |
| 运行中或正在停止 | 「添加图片」不可用。运行中沿用文字插话，待停止完成后按会话状态恢复图片入口。 |
| 模型不支持图片 | 当会话的当前模型不支持图片输入时，「添加图片」不可用并说明原因。已有图片草稿在发送时遇到此限制，保留图文并提示移除附件后可以发送文字。 |

### 格式和用量

以下为首版建议值，正式上限在技术方案中结合首个支持模型和请求体限制核定。客户端和服务端采用一致的规则，大小按原始文件字节数计。

| 对象 | 限制 | 超限或校验失败 |
| --- | --- | --- |
| 图片格式 | JPEG、PNG，文件内容应能正常解码 | 跳过该文件，显示文件名和失败原因。 |
| 单张图片 | 5 MiB | 跳过该文件并提示单张上限。 |
| 每条消息 | 4 张，含草稿中已添加的图片 | 按选择顺序加入有效图片直至达到上限，并提示超出的图片。 |

同一批选择中符合限制的图片和已编辑文字保留。服务端拒绝提交时，整条消息保持草稿状态，输入区说明原因，用户可以修正后重试。

### 历史与失败

- 服务端接受消息后清空对应草稿。用户消息按发送顺序展示图片缩略图，可点开大图。刷新、重新打开会话或查看已归档会话时，图片仍可查看。删除会话时一并清理其附件。
- 附件随用户消息进入模型上下文。原消息仍在模型上下文中时，用户可以在后续轮次用文字指代该图片。上下文压缩或裁剪后，历史图片仍可查看，用户可重新附图以供模型分析。
- 服务端确认未接受该消息时，保留文字和图片草稿并允许重试。连接中断且提交结果未知时，先确认已有运行或从会话恢复状态，避免重复创建用户消息。已接受消息后的模型失败或用户停止，沿用当前运行状态反馈，已提交的用户消息和图片仍可查看。

## 保持不变

- 纯文本消息使用现有发送、流式回复、停止和插话流程。已有纯文本会话按原样展示。
- 归档会话保持只读。项目选择和会话可写条件继续沿用当前规则。

## 验收标准

| 场景 | 可观察结果 |
| --- | --- |
| 发起图文对话 | 在 Web 和 macOS 桌面端选择多张合规图片，删除其中一张，再发送文字和保留图片。历史只展示实际发送的图片，顺序与草稿一致。 |
| 模型确实收到图片 | 使用支持图片输入的模型，发送一张含随机短码的测试图，文件名和文字均不含短码。验证模型请求包含实际图片输入，且模型能读出短码。首条消息和后续图文消息各覆盖一次。原消息仍在上下文中时，追加一轮纯文本追问并验证模型仍可引用图片。 |
| 纯图片与空输入 | 仅添加一张图片可以发送。移除全部附件后，空白输入无法提交。 |
| 切换会话 | 在草稿中添加图片和文字后切换会话，新会话输入框为空。切回原会话时，已发送的消息和附件仍可查看。 |
| 无效和超限文件 | 一次选取合规图片、伪装为 JPEG 的非图片文件、超出单张大小限制的图片，以及数量超限的图片。仅合规且位于上限内的图片进入草稿，每种拒绝原因可辨认。直接提交包含无效图片的请求时，服务端拒绝整条消息。 |
| 模型能力和运行状态 | 不支持图片的模型禁用添加入口，直接提交图文消息时也会被服务端拒绝。纯文本可发送，运行中可照常插话。 |
| 提交失败和恢复 | 分别验证服务端拒绝提交、接受后连接中断、运行开始后模型报错，以及用户主动停止。未接受的消息可从原草稿重试，已接受的消息只显示一次，已发送图片可查看。 |
| 历史与清理 | 刷新、切换回来或打开已归档会话后可查看已发送图片。删除会话后，其附件随会话清理。 |
