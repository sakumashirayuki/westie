# 飞书单聊绑定会话（链路验证版）产品方案

状态：产品方案，待评审。本文描述用户体验、产品规则与验收范围；事件接入方式、数据结构、进程与部署形态等具体实现另在技术方案中确定。

## 当前实现

Westie 的会话必须绑定一个工作目录和执行模式，由用户在界面上通过目录选择流程创建。会话创建后，用户在网页界面发送消息：会话空闲时开始一轮任务；任务进行中可以继续追加消息，模型把追加消息当作本轮的补充指令（steering）。任务由服务端持有，关闭网页不影响执行；任务结束后，最终回答保存在会话历史中。

任务需要批准工具操作时，用户必须在网页界面回应批准；目前没有网页之外的通知和操作入口。Westie 不连接任何外部聊天渠道，离开网页就无法发起任务、追加消息或收到任务结果。

## 背景与目标

最终目标是做成类似 dsh-superagent 的形态：飞书连接一个调度者，由它把工作派给绑定本地目录的会话执行。完整形态分阶段推进，本方案只覆盖第一步。

第一步的目标是**验证飞书与 Westie 之间的双向链路**：用户把一个已经存在的 Westie 会话与「自己和机器人的飞书单聊」绑定，之后在单聊里发文本消息即可驱动该会话，并在单聊里收到任务结果。

本步不引入调度者、工单或自动创建目录的能力，只回答三个问题：

1. 飞书消息能否可靠地到达指定的 Westie 会话；
2. 会话的任务状态和最终回答能否可靠地回到发起消息的单聊；
3. 绑定关系的授权、维护和异常提示是否成立。

预期可观察结果：用户不打开 Westie 网页，仅通过飞书单聊就能让一个已有会话完成一轮任务并收到完整回答；重复发送、网络重试等情况不会产生重复任务。

## 范围

P0 用户旅程：

- 入口：用户在 Westie 界面对一个已有会话发起飞书绑定；
- 授权：用户在与机器人的飞书单聊中完成绑定；
- 使用：在单聊发送文本消息驱动该会话，任务进行中可追加消息；
- 回收：在单聊或 Westie 界面收到任务结果、失败提示和需要批准的提醒；
- 恢复：可解除绑定，会话被删除后绑定关系不再生效。

P1 支持：绑定状态在 Westie 界面可见；绑定码过期可重新生成。

明确不做：群聊、非文本消息、在飞书内批准工具操作、流式输出、自动创建会话或工作目录、调度者与工单、多来源（GitHub 等）、多个 Westie 进程同时接入。

## 概念

| 名称 | 含义 |
| --- | --- |
| 飞书单聊 | 某个飞书用户与机器人之间的一对一聊天。一个用户与一个机器人只有一个单聊，作为绑定和回复的唯一对象。 |
| 机器人 | 企业自建飞书应用开启的机器人能力，用户通过它与 Westie 通信。 |
| 绑定 | 一个飞书单聊与一个 Westie 会话之间的一一对应关系。绑定后，单聊消息驱动该会话，结果发回该单聊。 |
| 绑定码 | 用户在 Westie 界面发起绑定后获得的一次性短时验证码，用户把它发给机器人完成授权。 |
| 一轮任务 | 会话空闲时，一条用户消息触发的一次完整执行。任务进行中该会话不接受新的独立任务。 |
| 追加消息 | 任务进行中用户继续发送的消息，作为对当前任务的补充指令，不另开任务。 |

术语沿用现有 Westie 语义：「追加消息」即现有 steering 能力在飞书渠道的呈现，本方案不为它新增排队或调度规则。

## 功能需求

### 前置：开启飞书接入

- 使用者（Westie 的操作者）需要先在飞书开放平台创建企业自建应用、开启机器人能力、授权机器人读取单聊消息和以机器人身份发消息，并让应用在自己的可用范围内、发布生效。未完成这些配置时，Westie 表现与现状完全一致：界面不出现飞书绑定入口，不存在任何飞书相关行为。
- 配置完成后，机器人可被企业内其他人搜索到。任何能与机器人单聊的人都可能发消息，因此**绑定码是唯一的授权入口**：没有有效绑定的单聊不能接触任何会话（规则见「单聊消息处理」）。

### FR-01 发起绑定（Westie 界面）

[打开绑定弹窗原型](../wireframes/feishu-binding-dialog.wireframe.html)，包含未绑定、已绑定、绑定码已过期三种状态，以及侧栏中已绑定会话的标记。原型使用示例数据，不会生成真实绑定码。

- 入口：每个会话提供「绑定飞书单聊」操作，打开绑定弹窗。
- 未绑定状态下，弹窗展示一组新生成的绑定码、有效期和操作指引（「在飞书中搜索机器人，向它发送这组码」）。
- 绑定码规则：

| 规则 | 行为 |
| --- | --- |
| 一次性 | 绑定成功后立即失效，不能用于第二次绑定。 |
| 短时效 | 超过有效期未使用自动失效；有效期具体时长在技术方案中确定。 |
| 同时唯一 | 一个会话同一时间只有一组有效绑定码；重新生成后旧码立即失效。 |
| 仅授权本会话 | 绑定码只代表用户对「这一个会话」的授权，不产生其他会话的访问权。 |

- 绑定成功后，弹窗和会话列表展示「已绑定飞书」状态；绑定完成前用户可以关闭弹窗，关闭不使已生成的绑定码失效。
- 会话已处于绑定状态时，弹窗不再生成新码，改为展示绑定状态和「解除绑定」操作（见 FR-05）。

### FR-02 完成绑定（飞书单聊）

- 用户在单聊中向机器人发送绑定码，机器人校验通过后完成绑定，并在单聊回复绑定成功，指明对应的会话（用会话标题或工作目录名帮助用户辨认）。
- 绑定结果：该单聊与该会话一一对应。一个单聊最多绑定一个会话；一个会话最多被一个单聊绑定。

| 绑定码情况 | 机器人回复 |
| --- | --- |
| 有效且会话、单聊均未绑定 | 绑定成功，说明对应的会话。 |
| 无效或已被使用 | 提示绑定码无效，引导回 Westie 界面重新生成。 |
| 已过期 | 提示已过期，引导重新生成。 |
| 目标会话已被其他单聊绑定 | 提示该会话已绑定，需先在 Westie 界面解除原绑定。 |
| 当前单聊已绑定其他会话 | 提示本单聊已有绑定，需先发送解绑指令再绑定新会话；不自动替换原有绑定。 |

- 绑定关系以绑定码校验成功时为准；网络重试导致的重复提交不产生第二条绑定记录。

### FR-03 单聊消息驱动会话

[打开飞书单聊对话流原型](../wireframes/feishu-chat-flow.wireframe.html)，按时间顺序展示绑定、新任务、待批准提醒、追加消息、分段结果与解绑的完整对话，右栏列出异常回复。

绑定成功后，单聊消息按以下规则处理。处理顺序自上而下，命中第一条即停止：

| 场景 | 产品行为 |
| --- | --- |
| 群聊中的任何消息 | 机器人不响应、不发起任何任务。本版只服务单聊。 |
| 机器人自己发出的消息 | 忽略。 |
| 空消息或仅含空白 | 忽略，不回复。 |
| 非文本消息（图片、文件、语音、卡片等） | 回复说明当前仅支持文本消息，不发起任务。 |
| 文本超过长度上限 | 不发起任务，回复说明消息过长及上限；上限取值在技术方案中确定，需同时满足飞书单条消息与 Westie 输入限制。 |
| 未绑定单聊的普通文本 | 回复使用引导：说明机器人只响应已绑定会话，并简述绑定方式；不接触任何会话内容。 |
| 绑定码、解绑指令 | 按 FR-02、FR-05 处理。 |
| 已绑定，会话空闲，文本有效 | 开始一轮新任务，回复一条简短确认（说明已收到、开始处理），任务结束后按 FR-04 回复结果。 |
| 已绑定，任务进行中，文本有效 | 作为追加消息交给当前任务，回复一条简短确认（说明已追加到当前任务）；不另开任务。 |
| 已绑定，但会话已被删除 | 视为未绑定：回复提示原会话已不存在、绑定失效，引导重新绑定。 |

补充规则：

- **幂等**：同一条飞书消息因平台重试等原因被送达多次时，只产生一次效果（一个任务或一条追加消息），用户不会看到重复确认和重复执行。
- **忙闲竞态**：消息判定为空闲、实际发起时会话已开始其他任务的，该消息按追加消息处理，不向用户报错。
- **追加消息受限**：当前任务允许挂起的追加消息数量和单条长度沿用 Westie 现有上限。达到上限或内容超限时，机器人回复明确原因（如「当前任务待处理的追加消息已满，请稍后再发」），消息不进入任务。
- **追加消息的采纳时机**：沿用现有任务语义，由模型在当前执行中采纳；机器人不承诺追加内容一定改变当前任务走向。
- 飞书消息与网页界面操作的是同一个会话：网页上可见飞书发起的任务和消息，飞书发起的任务也可在网页上查看、取消和批准。

### FR-04 任务状态与结果回到单聊

- **最终结果**：任务正常结束后，机器人把最终回答发回发起任务的单聊。回答过长时拆成多条连续消息发送，用户能收到完整内容，不因长度截断。
- **失败与取消**：任务失败或被取消时，机器人发送一条结果通知，说明终态和可理解的失败原因；不在单聊里重复内部错误细节。
- **需要人工批准**：任务执行中需要用户在网页界面批准工具操作时，机器人向单聊发送一条提醒，说明任务正在等待批准、需要回到 Westie 界面操作。本版不支持在飞书内批准；用户未批准期间任务维持现有等待行为。
- **通知克制**：除「收到确认、需要批准、最终结果（含失败/取消）」三类通知外，任务进行过程中的步骤、工具调用等过程信息不推送到单聊。
- **发送失败**：结果通知暂时发送失败时进行重试；若会话与单聊仍处于绑定状态，用户最终应能收到结果。重试后仍无法送达（例如机器人已无该会话话权限）时保留 Westie 会话内的完整结果，不因此影响任务本身，失败情况在 Westie 侧可被操作者发现。
- 结果只发回绑定的单聊，不向其他会话或群聊转发。

### FR-05 解除绑定

- 两个入口等效：
  1. Westie 界面绑定弹窗中的「解除绑定」；
  2. 在已绑定单聊中向机器人发送解绑指令。
- 解除后：单聊消息立即按未绑定规则处理（FR-03），不再驱动该会话；会话及其全部历史保留，网页使用不受影响。
- 解除不需要二次确认，但机器人在单聊回复解绑成功；界面入口即时更新为未绑定状态。
- 会话被删除时，其绑定关系一并失效，无需用户手动解绑；此后该单聊的下一条消息按未绑定引导处理。
- 解除绑定不影响已经结束或正在进行的任务：进行中的任务继续执行，其结果仍发回该单聊一次，此后不再有任何消息来往。[Assumption, TBD：也可选择解除后进行中任务的结果不再推送，需评审确认]

### FR-06 绑定状态在界面可见

- 会话列表中已绑定飞书的会话有明确标记，帮助用户辨认哪些会话会被飞书驱动。
- 绑定弹窗可区分三种状态：未绑定（展示绑定码）、已绑定（展示单聊归属与解绑入口）、绑定码已过期（展示重新生成）。
- 绑定关系变化（成功绑定、解除绑定）在界面刷新后正确反映；正在运行任务的状态显示与现有行为一致。

### 原型

- [绑定弹窗原型](../wireframes/feishu-binding-dialog.wireframe.html)：未绑定（绑定码与操作指引）、已绑定（单聊归属与解绑入口）、绑定码已过期三种状态，以及侧栏的已绑定标记。
- [飞书单聊对话流原型](../wireframes/feishu-chat-flow.wireframe.html)：绑定成功到解绑的完整对话，含待批准提醒、追加消息确认、长回答分段送达，以及未绑定、非文本、队列已满、会话已删除、群聊等异常回复。

原型展示主要布局和对话节奏；本文定义产品行为。原型中的绑定码、会话标题、消息内容和时间均为示例。

## 异常与边界情况

| 情况 | 用户可观察行为 |
| --- | --- |
| Westie 未启动或飞书连接中断 | 机器人无回复；连接恢复后服务继续，不保证补发断线期间发送的消息，用户需要重新发送。 |
| 绑定码在用户发送前被重新生成 | 旧码提交时按「无效或已过期」处理。 |
| 同一用户在多个设备上与机器人聊天 | 仍是同一个单聊，绑定关系和消息行为不变。 |
| 同一应用凭证被多个 Westie 进程同时使用 | 本版不支持，消息可能被任一进程接收而导致行为不确定；部署限制在技术方案中写明，界面不为这种情况提供产品兜底。 |
| 飞书平台重复推送同一事件 | 按幂等规则只生效一次。 |
| 用户在网页端取消了飞书发起的任务 | 任务取消，机器人按 FR-04 发送取消通知。 |
| 用户在网页端与飞书同时发送消息 | 统一服从会话「同一时间只有一个任务」的现有规则：先到的开始任务，其余按追加消息或忙闲竞态规则处理。 |

## 保持不变与首版范围

- 会话的创建方式、工作目录绑定、执行模式、审批机制、沙箱与权限语义、网页全部功能保持不变；本方案不改动任何现有会话规则。
- 飞书渠道是现有会话的一个额外入口，不改变会话历史、任务记账和项目归属。
- 首版只支持：企业自建应用、单聊、文本消息、一个单聊对一个已有会话。
- 首版不做：群聊和 @机器人、图片/文件/富文本、飞书内交互卡片与批准按钮、流式打字效果、消息编辑与撤回、机器人主动发起对话、按消息自动新建会话或目录、调度者与工单、消息记录在飞书侧的长期留存页面。

## 验收

1. 在 Westie 界面为一个已有会话生成绑定码，在飞书机器人单聊发送该码后，单聊收到绑定成功回复，Westie 界面显示该会话已绑定；重复使用同一绑定码被拒绝。
2. 绑定码过期、无效、目标会话已被其他单聊绑定、当前单聊已绑定其他会话四种情况，分别收到对应提示，且不产生绑定。
3. 在已绑定单聊发送一条文本消息，会话开始一轮新任务，单聊先收到收到确认；任务结束后单聊收到与 Westie 会话中一致的完整最终回答；网页端可见该任务及消息。
4. 任务进行中继续发送文本，消息作为追加消息进入当前任务并收到确认，不产生第二个并行任务；追加消息超数量或超长度时收到明确拒绝提示。
5. 模拟同一条飞书消息重复送达，只产生一次任务和一条确认。
6. 任务需要工具批准时单聊收到回网页批准的提醒；任务失败或被取消时单聊收到对应终态通知。
7. 非文本消息收到「仅支持文本」回复且不发起任务；群聊消息无任何响应；未绑定单聊收到绑定引导且无法驱动任何会话。
8. 长回答被拆成多条消息完整送达；结果通知发送失败经过重试后仍能送达，或在确实无法送达时不影响会话内已有的完整结果。
9. 从界面解绑、从单聊发送解绑指令两种方式都能解除绑定；解绑后消息按未绑定处理，会话历史保留；删除会话后，原单聊下一条消息得到绑定失效提示。
10. 未配置飞书应用时，Westie 行为与现状完全一致，无绑定入口、无飞书相关网络行为。

## 待确认问题

1. 运行中收到的消息默认按「追加消息」交给当前任务（推荐，复用现有能力），还是回复「任务进行中」并在任务结束后作为新一轮任务处理？
2. 解除绑定时，已经在运行的任务其结果是否仍发回原单聊一次？当前默认：仍发送一次。
3. 机器人对新任务和追加消息是否都需要「收到」确认？当前默认：都回复简短确认，便于链路验证；后续可按更少打扰的原则收紧。
4. 绑定码有效期与单条消息长度上限的具体取值，在技术方案中结合飞书与 Westie 现有限制确定。
5. 是否需要可配置的飞书用户白名单（仅允许指定用户绑定）？当前默认：不设白名单，绑定码是唯一授权入口；如团队环境需要再加入口。
