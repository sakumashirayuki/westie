# Stop Hook 产品方案

状态：待实施。事实基线：`262ff2c4b6bf6d247d46f59609ee1c9897b10a31`。
对应[技术方案](./2026-10-23-stop-hook-technical-spec.md)。

## 1. 当前实现

用户发起任务后，Agent 调用工具、修改文件并生成回答。模型返回最终回答时，Harness 检查是否还有子任务或用户追加消息需要处理；条件满足后发布回答，保存本轮结果并结束执行。

当前结束判断依赖模型返回的响应类型。程序没有执行项目自定义的完成检查。已有 Todo 由模型维护，状态不会阻止执行结束。

历史自举中发生过任务未完成却输出交接摘要并结束的情况。10 月 10 日异步子 Agent 开发的原始记录显示，编译仍报错时模型输出了摘要。该记录证明需要一个结束检查入口；模型偏离任务的根因仍未确定。Stop Hook 的效果以新增验收结果为准。

## 2. 存在的问题

1. 项目已有明确、可执行的完成条件时，当前 Harness 无法在结束前自动执行这些条件。
2. 检查发现缺项后，需要用户再次发送消息，Agent 才能继续补做。
3. 模型的结束声明、检查脚本运行成功、项目验收通过需要分别表达，避免混为同一结果。

## 3. 目标实现

### 3.1 最小使用示例

用户要求修复一个函数，并要求指定测试通过。项目配置一个检查脚本：

```json
{
  "command": "node .agents/check-completion.mjs",
  "timeoutMs": 30000,
  "maxContinuations": 2
}
```

配置保存为项目内的 `.agents/stop-hook.json`。Agent 准备提交最终回答时，Harness 执行该脚本。

脚本发现测试失败，输出：

```json
{"decision":"block","reason":"test/parser.test.ts 的空输入用例仍失败，请修复后重新验证。"}
```

Harness 把具体原因交给 Agent，Agent 在当前 Run 内继续工作。修复后再次准备结束，脚本输出：

```json
{"decision":"allow"}
```

Harness 才发布这次最终回答。用户无需为这一轮补做发送“继续”。

### 3.2 首版范围

- 支持 Web 运行台及 Electron 桌面版的主 Agent，两者使用相同服务端实现。
- 每个项目配置一个脚本入口；当前 Run 等待脚本结果，服务端继续处理其他请求。配置缺失时维持现有行为。
- 脚本负责具体检查，也可以自行调用模型。Harness 负责触发、解析结果、继续执行或结束。
- 检查发生在模型正常返回最终回答、当前子任务和用户追加消息处理完毕之后。
- CLI、子 Agent 自身、摘要调用保持原有结束方式。
- 配置通过本地文件维护；首版不增加设置面板、多个 Hook 编排、后台调度或跨 Run 自动续跑。

**配置数量。** 当前方案选择每个项目一个 Hook 入口，用于复用现有单次命令执行和审批流程。该数量属于首版范围选择，技术上可以扩展为多个入口。一个脚本可依次执行测试、检查文件和调用模型，最后汇总为一个 allow/block；检查顺序、失败后是否继续及原因汇总由脚本负责。Harness 首版只展示这一次脚本执行，不分别管理脚本内部各项检查。

**进程关系。** 每次触发检查，Harness 服务端启动一次独立的脚本进程，通过 stdin 发送检查输入，通过 stdout 接收决策。Agent 的执行循环运行在服务端进程内，等待脚本返回；前端仍可响应操作，服务端仍可处理其他会话。检查脚本每次执行后退出，下次检查重新启动；它没有单独的 Agent 会话，也不会自动继承主 Agent 的模型实例或内存状态。

同一 Run 的检查按顺序执行。不同会话可以同时运行各自的检查进程；共享工作区中的脚本应自行处理并发访问。取消或超时通过现有进程管理终止该次检查及其后代。

### 3.3 用户可见行为

| 情况 | 行为 |
| --- | --- |
| 没有配置 | 与当前版本一致 |
| 检查运行中 | Run 保持运行；工具轨迹显示 `stop_hook`、命令与执行状态；用户仍能停止、追加消息或切换会话 |
| 脚本允许结束 | 发布最终回答，按现有方式保存并完成本轮 |
| 脚本要求继续 | 工具轨迹显示“要求继续”和原因；模型收到原因，在当前 Run 内补做 |
| 脚本报错、超时、输出非法 | 本轮失败，显示检查错误；保留已经完成的工作与记录 |
| 用户拒绝脚本审批 | 本轮失败并说明检查未获授权，不自动放行或重试审批 |
| 超过允许补做次数 | 本轮失败，显示最后一次拒绝原因及次数限制 |
| 用户停止 | 取消检查进程和本轮执行，沿用现有取消行为 |
| 模型步数耗尽 | 沿用现有 `step_limit` 交接，停止自动补做；界面说明“步数已用尽，交接内容未经过完成检查” |

检查启用后，候选回答先暂存。通过检查才显示最终回答；被拒绝的候选不会作为完成答复显示。模型最终返回工具调用时，其说明文字在该步类型确定后显示。这会降低启用 Hook 时正文预览的即时性。

脚本执行成功且返回 `block` 时，脚本运行本身成功，任务仍需要继续。界面应显示这一区别。

### 3.4 次数和故障

`maxContinuations` 表示 Hook 最多允许要求 Agent 补做多少次，默认 2 次。初次检查拒绝 → 第一次补做 → 再检查拒绝 → 第二次补做 → 第三次检查仍拒绝，则本轮失败。第三次允许时正常完成。

该限制与现有模型步数上限同时生效。脚本自身故障直接报告失败，不让模型反复修复检查脚本，也不把故障转成放行。用户可以修复配置后重新发起任务。

### 3.5 追加消息与刷新

脚本执行期间收到新用户消息时，允许该次检查完成；合法的检查结果只作为未应用记录，旧候选回答作废。Agent 先处理新消息，再对新的候选回答重新检查。被作废的检查不消耗补做次数。脚本发生故障时沿用失败行为，界面明确展示错误。

刷新或切换会话不停止检查。可回放的事件恢复工具轨迹；回放日志超限时沿用现有快照恢复运行状态和待审批项，恢复后可继续接收检查结果。首版不承诺恢复已丢弃的全部中间轨迹。

### 3.6 权限与沙箱

Hook 以当前项目为工作目录，沿用会话执行模式、环境白名单、资源限制和取消机制。

- `workspace_sandbox`：执行前使用现有审批卡片确认命令，首版只允许单次批准。
- `full_access`：沿用当前免审批行为，命令仍在 Full Access Seatbelt 策略内执行。
- Hook 不获得额外的宿主执行权限。需要联网或读取项目外配置的脚本，应在具备对应权限的会话中使用。
- Harness 不向脚本自动提供模型 API Key。脚本自行管理模型服务配置与费用，其调用用量不纳入 Harness 的模型用量统计。

Full Access 内也不能再次启动 Seatbelt。Hook 如果运行测试，须遵守仓库 `AGENTS.md` 的测试规则：可运行的检查继续执行，需要真实创建沙箱的用例标记为待宿主验证。项目要求这些用例必须通过时，应在宿主完成验证；Hook 无法通过权限切换补齐它们。

### 3.7 完成检查的边界

检查结论取决于用户编写的脚本。脚本可以检查指定文件、测试结果或调用模型判断；Harness 不内置通用的“任务完成”判定，也不保证脚本覆盖了全部需求。

检查脚本与配置可能属于 Agent 正在编辑的仓库。首版冻结每轮开始时读到的配置，脚本文件在执行时读取；不提供防篡改验收机制。要求独立验收的任务仍需外部审查。

## 4. 具体改动

1. 加载项目级 Stop Hook 配置，明确非法配置错误。
2. 在最终回答被接受前执行脚本，根据结果放行或继续当前循环。
3. 把检查结果记入现有会话记录，注明来源为 Stop Hook；实际应用的拒绝原因进入下一次模型输入。记录只保存检查结论，被拒绝的候选回答全文不写入历史。
4. 使用现有审批和工具轨迹显示检查过程与结果；补充步数耗尽的交接提示。
5. 增加脚本输入输出协议、次数上限以及取消和故障验收。

## 5. 保持不变

- 无配置项目的模型调用、工具权限和结束流程。
- 子 Agent 生命周期、MCP、Skill、模型重试和上下文压缩的职责。
- 用户停止、HTTP 断连与后台 Run 生命周期的关系。
- SQLite 表结构、现有 Run 状态枚举和模型用量口径。
- 宿主验收与代码审查要求。

## 6. 产品验收

| 场景 | 可观察结果 |
| --- | --- |
| 无配置 | 原有任务正常完成，无 `stop_hook` 执行 |
| 第一次即放行 | 检查后出现最终回答，整轮只有一次完成事件 |
| 拒绝一次后放行 | 先显示具体缺项，Agent 实际补做，第二次检查通过才发布最终回答 |
| 始终拒绝 | 默认两次补做后失败，显示最后原因，无无限循环 |
| 脚本异常 | 错误可见，候选回答没有被标为完成 |
| 检查中取消 | 脚本和其后代进程被清理，Agent 不再继续工作 |
| 检查中追加需求 | 旧回答被丢弃，新需求被处理后重新检查 |
| 检查中刷新 | Run 持续执行，可恢复状态和待审批项 |
| 工作区沙箱审批 | 未批准前脚本不执行；拒绝后不发布候选回答 |
| 步数耗尽 | 不再执行 Hook 或自动补做，界面明确显示交接语义 |
| 脚本运行测试 | 真实沙箱测试在宿主验证；跳过项和 Hook 放行不被描述为全量验收通过 |

以上为待执行验收标准。方案阶段只完成源码核对和文档检查。
