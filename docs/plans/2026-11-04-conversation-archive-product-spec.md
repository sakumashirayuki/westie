# 会话归档产品方案

状态：产品方案，待实施。本文描述用户体验和验收范围；数据库迁移、worktree 清理的失败恢复、只读权限校验的具体实现另在技术方案中确定。

## 当前实现

Westie 的侧栏按项目分组展示全部历史会话，每个会话行支持重命名和删除。删除会从 SQLite 数据库移除会话及其全部轮次、Run 和转录消息，不可恢复。会话一旦创建就始终出现在侧栏，除非被删除。

会话可以使用普通目录、Git 主目录或新建 worktree 作为工作目录。新建 worktree 时，Westie 在 `~/.westie/worktrees/` 下创建工作目录并登记到 `worktree_operations` 表，操作记录通过 `conversation_id` 关联到会话。worktree 目录只在会话创建时产生，目前没有在会话结束后自动清理的机制。

当前会话的可写操作包括：发起 Run（`runs:stream`）、追加消息（`runs:steer`）、重命名、删除。运行中的会话不能重命名或删除。

当前代码依据：[会话列表](../../web/src/components/ConversationList.tsx)、[会话项路由](../../src/http/conversation-item-routes.ts)、[worktree 操作记录](../../src/infrastructure/sqlite/worktree-operation-store.ts)、[新建 worktree](../../src/application/worktree-creation.ts)。

## 存在的问题

1. 已完成或不再需要的任务没有“收起”方式，只能删除。删除会丢失完整历史，用户对已经产出结果的任务不敢轻易删除，导致侧栏越积越长。
2. 为某个任务创建的 worktree 在任务结束后仍占用磁盘和 Git 登记；用户需要手动去 `~/.westie/worktrees/` 清理，没有从会话侧直接清理的入口。
3. 侧栏没有区分进行中和已结束的任务，用户在长列表中找当前任务需要逐个辨认。

## 目标实现

用户可以把认为已经结束的会话归档。归档后的会话从侧栏主列表消失，集中在「已归档」区域中只读展示；归档同时清理该会话创建的 worktree（如有）。归档不删除数据库中的会话历史，也不提供恢复入口。

### 概念

| 名称 | 含义 |
| --- | --- |
| 归档 | 把会话标记为已结束，从侧栏主列表移除并禁用全部可写操作。数据库记录保留。 |
| 已归档区域 | 侧栏底部的独立分区，集中展示所有归档会话，支持展开和折叠。 |
| 只读 | 归档会话不能发起 Run、不能追加消息、不能重命名；只能查看历史内容。 |

### 首版范围

- 归档操作对未在运行的会话可用；运行中的会话不能归档，原因与删除一致。
- 归档是单向操作：本版本不提供取消归档（恢复）入口。归档会话如需重新使用，只能新建会话。
- 归档时若会话关联了 Westie 创建的 worktree，删除该 worktree 目录，本地分支保留（分支可能由用户带入或含有未合并的提交，删除分支会造成不可逆丢失）；使用主目录、已有 worktree 或普通目录的会话不涉及清理。
- 归档会话完全从侧栏移除；通过侧栏底部「已归档」入口进入独立的归档视图，在该视图中按项目分组展示，与主列表同样的排序和分页规则。
- 归档会话打开后，历史消息、Run 轨迹、用量等全部只读展示；输入区禁用并提示该会话已归档。
- 不影响删除：归档会话仍可被删除，删除行为与当前一致。

**不包含：** 批量归档、归档搜索、按时间自动归档、归档内容导出、归档会话的恢复。

## 交互原型

归档会话完全从侧栏移除，侧栏只保留活动会话。归档内容通过侧栏底部「已归档」入口进入独立视图。以下原型覆盖四个关键状态，文件位于仓库根目录：

- [侧栏与归档入口](../../docs/wireframes/archive-sidebar-menu.wireframe.html)：侧栏只展示活动会话；会话行操作菜单新增「归档」项；侧栏底部有「已归档」入口链接（非展开分区）。
- [归档确认对话框](../../docs/wireframes/archive-confirmation.wireframe.html)：点击「归档」后弹出，逐条说明后果，确认按钮为唯一提交入口。
- [归档会话列表](../../docs/wireframes/archive-list-view.wireframe.html)：点击侧栏「已归档」后，主区域切换为归档会话列表，按项目分组，只读。
- [归档会话只读详情](../../docs/wireframes/archived-conversation-readonly.wireframe.html)：从归档列表点击某个会话进入，顶部有「返回归档列表」，输入区禁用并提示只读。

## 具体改动

### 侧栏

```text
项目
▾ my-agent-harness                         ＋
    ● 实现归档功能
      Worktree · feat/archive · Sandbox
    ○ 排查启动问题
      主目录 · main · Sandbox
▾ another-project                           ＋
    ○ 整理设置页面
      主目录 · develop · Sandbox

──────────
已归档
MCP 服务器
```

- 侧栏只展示未归档（活动）会话；归档会话完全从侧栏移除，不出现在任何项目分组中。
- 侧栏底部、MCP 服务器入口上方新增「已归档」入口链接，仅作为进入归档视图的导航，不在侧栏内展开任何归档会话列表。
- 活动会话行的操作菜单新增「归档」，位于「重命名」和「删除」之间；运行中的会话「归档」与「删除」一并禁用。
- 归档会话不在侧栏展示，因此不涉及侧栏内的选择与切换。

### 归档视图

点击侧栏「已归档」入口后，主区域切换为归档视图，侧栏仍展示活动会话：

- 归档视图顶部显示标题「已归档会话」与会话数量。
- 归档会话按项目分组、卡片形式展示，沿用主列表的项目识别与排序规则。
- 每张卡片显示会话标题、工作目录类型与归档时间；卡片操作菜单只保留「删除」。
- 点击卡片进入该归档会话的只读详情；详情顶部提供「返回归档列表」。
- 归档视图支持分页（加载更多），与活动会话列表一致。

### 归档操作

- 会话行操作菜单点击「归档」后，弹出确认对话框，说明：该会话将从主列表移除；关联的 worktree 目录将被删除，worktree 内未提交的更改会被丢弃；对应的本地分支会保留；操作不可撤销。
- 确认后执行归档。若该会话由 Westie 创建了 worktree，归档流程删除 worktree 目录、保留对应分支；用户无需手动清理目录，分支由用户按自己的 Git 工作流处理。
- 归档成功后，会话从侧栏消失；若该会话正在侧栏中选中，主区域切换为该会话的只读详情，侧栏选中态清除。
- 归档失败（如 worktree 清理异常）时，给出明确提示，不保留半归档状态：要么会话已归档且 worktree 已清理，要么会话保持原状。

### 归档会话的只读约束

从归档视图打开归档会话后：

| 区域 | 行为 |
| --- | --- |
| 顶部导航 | 显示「← 返回归档列表」，回到归档会话列表 |
| 项目栏 | 标注「已归档」状态标识 |
| 历史消息与 Run 轨迹 | 完整展示，与未归档会话一致 |
| 输入区 | 不展示输入框与发送按钮，页面直接结束于最后一条消息 |
| 会话标题 | 不可编辑；操作菜单不显示重命名 |
| 运行/停止按钮 | 不显示或置灰 |
| 删除 | 仍可删除，删除后从数据库永久移除 |

只读约束在服务端同样生效：对归档会话发起 Run、追加消息、重命名请求均被拒绝，不依赖前端禁用。

### worktree 清理

- 只清理 Westie 为该会话创建的 worktree（即 `worktree_operations` 中 `conversation_id` 指向该会话、且状态为 `completed` 的记录对应的 worktree）。
- 清理执行 `git worktree remove --force` 删除工作目录；worktree 内未提交的更改随目录一起丢弃。
- 本地分支一律保留，不执行分支删除：「检出已有分支」模式下分支本就属于用户；新建分支模式下分支也可能含有尚未合并或推送的提交。分支引用几乎不占磁盘，用户可在归档后自行合并或删除。
- 清理发生在归档流程内；若 Git 操作失败，归档整体失败，会话保持未归档状态，便于用户重试或手动处理。
- 使用主目录、已有 worktree（非 Westie 创建）或普通目录的会话，归档时不执行任何 Git 清理。

## 保持不变

- 会话的数据库记录、轮次、Run、转录消息在归档后完整保留，归档只改变会话的可见性与可写性。
- 未归档会话的全部行为不变：发起 Run、追加消息、重命名、删除、项目分组、分页。
- 删除行为不变：删除仍然从数据库永久移除会话及其全部数据，归档不替代删除。
- worktree 创建流程不变：新建会话创建 worktree 的方式、目录结构和操作日志登记不变。
- 项目识别与工作目录实时状态探测不变，归档会话同样展示其项目归属和目录信息。
