# 跨会话记忆需求

## 当前实现

Harness 已支持用户为同一项目选择主工作目录、已有 worktree 或创建新 worktree。项目会话按现有项目身份归组；同一 Git 仓库的不同 worktree 共享项目身份，独立 clone 分别归组。当前会话可以使用自己的历史，但新会话没有跨会话记忆。

## 存在的问题

用户在一个会话中说明过的项目事实，在同一项目的新会话中需要重新说明。记忆可能不断增加，用户也可能直接编辑记忆文件，因此需要让用户知道哪些内容被加载，以及如何找回未加载的内容。

## 目标实现

用户在仓库的 worktree A 说“记住，集成测试需要先启动 Redis”；Agent 保存后告知结果。用户在同一仓库的 worktree B 新建会话并要求运行集成测试时，Agent 可以读取同一份记忆，并结合当前任务使用。用户可以继续要求“修改”或“忘记”这条记忆。

第一版覆盖以下行为：

- **共享范围**：同一 Git 仓库的主工作目录、worktree 和子目录共用项目记忆；不同仓库及独立 clone 分开。普通目录按项目目录隔离。
- **写入方式**：用户明确提出“记住 / 修改 / 忘记”时，Agent 执行相应操作并报告结果。记忆可由用户直接查看和编辑。
- **存储位置**：项目记忆以 Markdown 文件保存在 Harness 管理的用户数据目录中，不随项目仓库提交。
- **记忆加载**：新 Run 加载有大小限制的记忆索引；详情按需读取。用户手工写入过大的索引时，文件保留完整，系统提示部分内容未加载，并支持继续读取；截断后的内容不保证被自动召回。
- **并发修改**：同一服务内的会话可能同时修改同一份记忆；写入按顺序执行并在写前检查文件是否发生变化，冲突时不覆盖，Agent 重新读取后处理。
- **删除范围**：忘记操作修改或删除长期记忆文件中的相应内容，不删除历史会话记录或既有 Run 的提示词记录。

已有项目归属无法确定时，普通会话仍可继续，记忆不可用的状态应明确告知。索引可能过期，Agent 使用时应结合当前任务判断是否需要核对。

## 保持不变

项目的会话和 worktree 创建方式、工作区工具访问规则、历史会话记录和现有数据库结构保持不变。第一版不自动从会话提取记忆，也不提供个人跨项目记忆、跨机器同步或独立 clone 共享。

## 评测与验收

使用真实模型评估 Agent 是否能正确操作和使用记忆，复用现有评测系统记录结果。跨会话评测覆盖同一仓库的不同 worktree，使用隔离的测试记忆目录。

| 场景 | 操作与验收 |
| --- | --- |
| 跨 worktree 记住与召回 | 在 A 中明确记住只有用户知道的虚构事实；在同仓库 B 的新会话中完成相关任务，检查事实被正确保存和使用 |
| 修改与忘记 | 修改后新会话使用新内容；忘记后检查长期记忆及后续加载不再包含对应内容 |
| 项目隔离 | 仓库 A 保存事实后，独立仓库 B 不应使用该事实；无关任务不应错误使用记忆 |
| 超限索引召回 | 手工将目标条目放在索引加载范围之后，检查原文件保留、截断提示和继续读取；单独统计 Agent 是否实际召回 |
| 上下文成本 | 相同模型和任务下比较空记忆、短索引与超限索引，记录任务结果、实际输入 Token 和工具调用次数 |

评测使用虚构事实、独立临时目录和预先固定的运行条件，分别记录成功、失败和异常。
