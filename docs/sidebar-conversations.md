# 侧栏会话区

左栏会话列表的呈现与操作语义。组件在 `web/src/components/Sidebar.tsx` 与 `ConversationList.tsx`，具体类名和 DOM 结构以代码为准。

## 会话条目

每个条目显示显示名、执行模式徽标、更新时间与会话 id 前 8 位。显示名取 `title ?? workspace.name`：用户设置过标题就显示标题，否则回退到工作区目录名。工作目录路径、类型和分支显示在会话详情中。

同一工作区可以有多个会话，标题为空时它们的显示名相同，可通过短 id 区分。

`GET /v1/agent/conversations` 返回列表展示和项目分组所需的摘要，包括 `workspace.name` 与项目归属；不返回工作目录路径或实时工作目录状态。`GET /v1/agent/conversations/{id}` 返回完整会话详情，包含工作目录路径、类型、分支和可用性。列表读取时，未识别项目的历史会话仍会尝试识别并回填归属。

## 运行状态标记

状态来自全局 `GET /v1/agent/runs:watch` 流，不是列表接口里的字段。连接建立时先收到 `snapshot`，之后每次状态变化收到 `run.state`；断线按 500/1000/2000/4000 毫秒退避重连，最多 5 次，重连后 `snapshot` 整表替换。

| `state` | 侧栏表现 |
| --- | --- |
| `running` | 绿色圆点，`aria-label="运行中"`，带呼吸动画（`prefers-reduced-motion` 下关闭） |
| `awaiting_interaction` | 橙色圆点，`aria-label="等待审批"` |
| `waiting_sub_agents` | 橙色圆点，附「等待子任务」一行文字 |
| `ended` | 条目从状态表移除，标记消失 |

状态表只在页面内维护。5 次重连全部失败后不再更新，侧栏会停在最后一次已知状态，界面没有"状态流已断开"的提示。

## 行内操作菜单

每个条目右侧只有一个「更多操作」触发器（三个点），`aria-label` 为 `会话操作 <显示名> <id 前 8 位>`。展开后是 Radix DropdownMenu 渲染的菜单项：

| 菜单项 | 空闲会话 | 有活动 Run 的会话 |
| --- | --- | --- |
| 重命名 | 可点，打开改名弹窗 | 禁用，附注「会话正在运行」 |
| 删除 | 可点，打开删除确认弹窗 | 禁用，附注「会话正在运行」 |

禁用状态写进菜单项的 `aria-disabled` 与附注文字，不靠颜色区分。Esc、方向键与焦点管理由 Radix 负责。

"有活动 Run" 指该会话出现在运行状态表里；服务端另有独立校验，绕过界面直接调接口会得到 409。

## 改名弹窗

输入框预填当前显示名（标题或工作区名），打开时自动聚焦并全选，右下角显示已输入字符数。

- 保存时先去掉首尾空白；结果为空即提交 `title: null`，恢复显示工作区名。
- 与当前值相同时不发请求，直接关闭。
- 服务端错误只做展示，输入框保持可编辑，改一下输入提示即消失，可直接重试。
- 服务端不改 `updated_at`，所以改名后条目停在列表原位，不会跳到顶部。

## 删除弹窗

需要二次确认。会话有活动 Run 时服务端拒绝删除（409），与界面禁用一致。删除成功后从列表移除；删的是当前会话则回到首页。

## 列表排序与分页

服务端 `ORDER BY updated_at DESC, id DESC`，前端 `mergeConversationSummaries` 用同样的比较函数，保证本地合并（新建、改名、删除）后顺序稳定。分页游标编码 `{v, updatedAt, id}`。
